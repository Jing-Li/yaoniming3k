# ADR-0018: 多周期共振框架

## Status
Proposed (未实现)

> **注意**：此方案为未来规划，代码库中尚未实现 MultiTimeframeEngine、TimeframeFilter 或 timeframe_sync 模块。BacktestEngine 仍为单周期模式。

## Context
当前回测系统仅支持单一时间周期（如仅 60m 或仅日线）回测，策略所有判断都建立在单一频率的 K 线序列之上。

蔡森理论的核心原则之一是 **"大周期决定小周期"**：

- **周线** 看长期方向（多/空/震荡）
- **日线** 看中期波段（建仓/止盈区间）
- **分钟线**（60m / 30m / 15m）看具体择时（入场/出场触发）

仅依赖单一周期会带来两类问题：

1. **方向缺失**：分钟级形态可能与日/周线方向相反，触发逆势交易
2. **假信号过多**：单一周期的形态在更大级别趋势下可能只是噪音

蔡森实战经验表明，多个周期方向一致（"共振"）时，形态信号的可靠性显著提升（蔡森本人称约 70% 胜率），周期冲突时则应放弃交易。

### 替代方案

1. **保持单周期**：实现简单但放弃了蔡森理论的核心优势
2. **多周期共振框架**：引入多频率数据流和层次化过滤
3. **多策略叠加**：每个周期独立运行一个策略实例，再融合结果（耦合度高、共振语义模糊）

## Decision

采用方案 2：构建多周期共振框架。

### 1. MultiTimeframeEngine

扩展 `BacktestEngine`，支持同步推进多频率数据：

- 接受多个 `DataSource`（每个对应一个频率）
- 内部维护时间游标，按最小频率推进
- 每次 `on_bar` 提供当前帧及所有更大周期的"已收盘最近一根"

### 2. TimeframeFilter

层次化信号过滤组件，将周期分为两类：

- **direction_tf**（方向周期）：周线/日线，确定大趋势方向
- **entry_tf**（入场周期）：60m / 30m / 15m，确定具体入场点

过滤规则：

- 入场信号方向 ≠ 方向周期方向 → **拒绝**（默认 wait 策略）
- 入场信号方向 == 方向周期方向 → **放行**，并给予 `resonance_boost` 置信度加成
- 多个方向周期均共振时，加成可叠加（受配置上限约束）

### 3. timeframe_sync 模块

处理不同周期 K 线的时间对齐：

- 将分钟线时间戳映射到对应的日线/周线收盘时间
- 保证策略在 entry_tf 的某根 K 线上看到的 direction_tf 数据是 **该时刻已收盘** 的最新数据，避免未来函数

### 4. 周期冲突处理

默认策略：**wait**（拒绝交易）。可配置 `conflict_policy`：

- `wait`：放弃信号
- `entry_only`：仅看入场周期（退化为单周期）
- `direction_only`：方向周期不共振则不持仓（已持仓则平掉）

### 5. 配置示例

```yaml
multi_timeframe:
  direction_tf: ["1d", "1w"]
  entry_tf: "60m"
  resonance_boost: 0.15
  conflict_policy: "wait"
```

## Consequences

### Positive
- 信号质量显著提升，假信号大幅减少
- 与蔡森"大周期决定小周期"理论对齐
- 共振机制提供可解释的置信度调整
- 周期冲突显式处理，逆势交易被自动屏蔽

### Negative
- 回测引擎需要重大扩展以支持多数据流推进
- 数据源需同时提供多个频率的 K 线（依赖 caisen-data 项目）
- 配置复杂度增加（多个周期的数据范围、对齐规则）
- 策略参数空间扩大（各周期权重、resonance_boost）
- 对历史数据完整性要求更高（任一周期缺失都会影响共振判断）
