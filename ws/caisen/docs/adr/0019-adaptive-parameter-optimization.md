# ADR-0019: 自适应参数优化引擎

## Status
Proposed

## Context
现有参数优化采用网格搜索（grid search）：

- 参数空间被预先离散为有限组合（当前约 ~1500 种）
- 每种组合执行一次完整回测，按指标排序选优
- 全部组合穷举，无任何剪枝

随着系统演进，网格搜索逐渐暴露多重瓶颈：

1. **维度灾难**：ADR-0018 多周期共振引入后，参数维度大幅增加（各周期权重、resonance_boost、conflict_policy 等），笛卡尔积导致计算量指数爆炸
2. **样本外失效**：网格搜索仅按全样本指标选最优，未做训练/测试分割，存在严重的过拟合风险
3. **市场结构变化（regime change）**：曾经最优的参数可能因市场结构变化而失效，需要周期性重优化
4. **缺乏重用**：每次优化都从零开始，未利用历史最优结果

### 替代方案

1. **保留网格搜索**：实现简单，但已无法承载多周期参数空间
2. **引入贝叶斯优化（Optuna TPE）+ Walk-Forward + 自适应触发**：兼顾搜索效率、泛化验证与持续演进
3. **遗传/粒子群算法**：实现复杂度高，对当前问题规模收益有限

## Decision

采用方案 2：构建自适应参数优化引擎。

### 1. 主优化器：Optuna

- 默认采样器：**TPE**（Tree-structured Parzen Estimator），高维空间下显著优于网格
- 默认剪枝器：**Median Pruner**，劣于历史中位数的试验提前终止
- 试验数（n_trials）和超时时间通过配置控制

### 2. Walk-Forward Validation

防过拟合的核心机制：

- 历史数据按时间序列等分为 N 段
- 每段内：前 70% **训练**（用于优化目标），后 30% **测试**（样本外验证）
- 窗口逐步向前滚动
- 最终目标值 = 各测试段指标的平均值（或加权平均）

### 3. AdaptiveOptimizer

基于性能监控触发增量重优化：

- 触发条件（任一满足）：
  - 近期实盘/滚动回测夏普比率较历史基线衰退 > 30%
  - 实际回撤超过历史最大回撤 1.5 倍
  - 距上次优化超过 K 个交易日
- 触发后采用 **warm-start**：以上次最优参数为中心，在邻域内继续搜索
- 与全量重优化共存（手动触发或定期触发）

### 4. 模式开关

保留多种优化模式以适配不同场景：

- `grid`：小参数空间快速验证
- `optuna`：默认主模式
- `adaptive`：定时/触发式增量优化

### 5. 多目标支持

支持加权多目标或 Pareto 前沿：

- 主指标：夏普比率
- 辅助指标：胜率、最大回撤、年化收益
- 通过配置权重合并为单一标量目标

### 6. 优化历史持久化

- 完整保存所有 trials 的参数与指标
- 支持回溯分析、参数稳定性研究、warm-start 数据来源

## Consequences

### Positive
- TPE 在高维空间下显著优于网格搜索，单次优化计算量下降
- Walk-Forward 提供样本外泛化能力评估，过拟合风险大幅降低
- 自适应机制实现"参数随市场演进"，无需人工干预
- 优化历史可回溯，支持持续迭代分析
- 多目标优化使得策略平衡更可控

### Negative
- 新增 `optuna` 第三方依赖
- CLI 需扩展 `optimize` 子命令（增加采样器、剪枝器、walk-forward、warm-start 等参数）
- 单次优化时间相对单条回测显著增加（虽然总组合数下降，但 Walk-Forward 多次回测）
- 调试复杂度上升（采样器随机性、剪枝时机）
- 对优化结果的解读门槛提高（需理解 TPE / Walk-Forward 概念）
