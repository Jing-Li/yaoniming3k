# DX Conventions

Shared protocols and knowledge base for the dx (Developer Experience / Frontend) pipeline. This skill does NOT execute independently — it is a **reference library** consumed by `dx-image-to-code`, `dx-url-to-code`, `dx-prototype`, and `dx-review`.

## Role in Pipeline

> **dx pipeline** · Shared Knowledge Layer
>
> | | |
> |---|---|
> | **Consumers** | `dx-image-to-code`, `dx-url-to-code`, `dx-prototype`, `dx-review` |
> | **Owns** | `references/` (design specs, quality rules, testing patterns) |
> | **Does** | Provide canonical standards for design system structure, anti-slop detection, performance auditing, interaction testing, and component initialization |
> | **Does NOT** | Execute any pipeline step, generate code, produce artifacts |

## Key Artifact: dx/design-system.md

The central artifact governed by these conventions is `dx/design-system.md` — the unified design baseline for a project.

- **Generated by**: `dx-image-to-code` or `dx-url-to-code` (Step 0)
- **Read by**: `dx-prototype` (style consistency), `dx-review` (conformance baseline)
- **Idempotent**: If it exists, read it; do not regenerate unless user explicitly requests redesign
- **Structure**: Defined in [references/design-tokens-spec.md](references/design-tokens-spec.md)

## Sources

These conventions synthesize knowledge from:
- **Frontend Design** (Anthropic) — anti-slop philosophy, intentionality, signature elements
- **UI-UX-Pro-Max** (nextlevelbuilder) — structured design tokens, priority-based rules
- **Web Artifacts Builder** (Anthropic) — React+TS+Tailwind+shadcn/ui scaffolding
- **Vercel React Best Practices** (Vercel) — 70 performance rules across 8 categories
- **Playwright Skill** (lackeyjb) — on-the-fly browser automation testing patterns
